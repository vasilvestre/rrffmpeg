rrffmpeg

A correct dispatcher for Jellyfin transcodes. It stands in for ffmpeg and sends each job to the machine that has the GPU. It never touches video quality, remuxing or encoding. Only dispatch.

Written in Rust. One dependency-free static binary, no daemon on the client, no database.

Why it exists

The maintained options are weak. The Python rffmpeg commits to SQLite with an fsync between "decide to run" and "run ffmpeg", marks a GPU host bad forever after one SSH error, and leaves orphan rows on SIGKILL. rffmpeg-go is archived. dffmpeg has the right architecture but is beta.

Meanwhile the layout "small GPU node plus separate storage host" is common in home labs: an Intel N100 with QuickSync on one side, the NAS on the other. The people running it have no maintained dispatcher.

  • 64 msdispatch with the journal on tmpfs
  • 2 to 4 sthe same dispatch when the fsync sits on the hot path
  • 1.54xrealtime, 4K HEVC HDR with tonemap_opencl
  • 2.67xrealtime, 1080p SDR

Features

  • Exact argument passthrough. file: prefixes, startup probes (-version, -encoders), stdin write from Jellyfin, stderr stats on stderr. Nothing is rewritten.
  • One binary, two names. Symlink it as ffmpeg and ffprobe, because Jellyfin derives ffprobe from the ffmpeg path.
  • Bookkeeping off the hot path. An append-only journal with a background flusher. The transcode starts at once.
  • In-process janitor. Retests unhealthy hosts, reaps orphans, requeues. No cron watchdog.
  • Cross-process concurrency cap. One lock file per worker slot, freed by the kernel when the process dies. The "host down" verdict is shared with an expiry, so one failure does not poison the others.
  • Capability-aware placement. Workers advertise vaapi, nvenc, qsv and their slot count. The scheduler matches instead of applying a global weight.
  • Path mapping in both directions. Longest-prefix mapping for input and output, so the worker can mount media and the HLS tmpfs at another root.
  • SSH transport. Zero install on the worker. A tiny agent daemon is planned to remove the per-job probe.
  • Priority as a hint. Probes poll for a slot faster than transcodes. Ordering across processes waits for the agent.

Install

Every v* tag publishes static Linux builds for x86_64 and aarch64 on the releases page, with a checksum next to each tarball. A static build needs no toolchain and no matching glibc on the Jellyfin host.

curl -LO https://github.com/vasilvestre/rrfmpeg/releases/latest/download/rrffmpeg-x86_64-unknown-linux-musl.tar.gz
sha256sum -c rrffmpeg-x86_64-unknown-linux-musl.tar.gz.sha256
tar xzf rrffmpeg-x86_64-unknown-linux-musl.tar.gz
sudo install -m 755 rrffmpeg-x86_64-unknown-linux-musl/rrffmpeg /usr/local/bin/rrffmpeg
sudo ln -sf /usr/local/bin/rrffmpeg /usr/local/bin/ffmpeg
sudo ln -sf /usr/local/bin/rrffmpeg /usr/local/bin/ffprobe

Point Jellyfin at /usr/local/bin/ffmpeg. Without a config file the binary runs the local ffmpeg and does nothing else, so the install is safe before the worker exists.

Configuration

The file is read from $RRFFMPEG_CONFIG, then $XDG_CONFIG_HOME/rffmpeg/config.toml, then ~/.config/rffmpeg/config.toml. Missing keys take the defaults below.

Top level

KeyDefaultMeaning
hosts[]Workers. Empty means every job runs locally.
state_dir~/.local/state/rrffmpegJournal, pid files and the coordinator slot files. Put it on a local filesystem; a slow disk adds fsync latency, it must not be shared over NFS.
queue_wait_secs600How long a job waits for a free worker slot before running locally.
down_ttl_secs60How long one process's "host down" verdict is trusted by the others. Expiry is the repair mechanism.
stderr_as_stdoutfalseCopy ffmpeg stderr to stdout, for Jellyfin builds that read probe output there.
ssh_binsshSSH client used for the transport.
local_ffmpegffmpegBinary used when a job runs locally. Point it away from the symlink or you loop.
local_ffprobeffprobeSame, for ffprobe.

One host

KeyDefaultMeaning
namerequiredSSH target: a hostname or an alias from ~/.ssh/config.
concurrency1Slots on this host. Each slot is an exclusive lock file, so a forked job cannot exceed it.
capabilities[]Advertised encoders, for example ["vaapi"].
ffmpeg_bininheritedffmpeg path on the worker.
ffprobe_bininheritedffprobe path on the worker.
paths[]Path maps, see below.

Path maps

Each entry rewrites a client prefix to a worker prefix, longest match first. The host probe stats every to root, so a dead mount marks the host down instead of failing each job with ENOENT. Map input and output separately: media and the HLS tmpfs are usually two different mounts.

Example

state_dir = "/home/alice/.local/state/rrffmpeg"
down_ttl_secs = 60

[[hosts]]
name = "worker"
concurrency = 2
capabilities = ["vaapi"]

# Input: media mounted at a different root on the worker.
[[hosts.paths]]
from = "/home/alice"
to = "/home/bob/media"

# Output: HLS segments on the client tmpfs, through a second mount.
[[hosts.paths]]
from = "/dev/shm/jellyfin-transcode"
to = "/home/bob/transcode"

Status

Working today: passthrough verified against real ffmpeg 8.0.1, one worker over SSH, path mapping both ways, journal plus janitor, per-host cap, capability match. Not yet: requeue after a dead client (needs the agent), priority ordering across processes, recorded-invocation replay.

Design choices and their costs are written down in the decision records.
