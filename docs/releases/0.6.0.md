# 0.6.0

Release date: 2026-11-17

Three keys and one protocol revision remove the shims the production pair kept
by hand. A v0.5.0 `config.toml` keeps working untouched.

## Additions

- `fallback_local` (default `true`). Set it `false` on a client with no GPU:
  an `ffmpeg` job that finds no worker slot exits 1 and logs
  `no worker slot after <N>s and fallback_local is false`, instead of encoding
  in software on the client. A local `ffprobe` still runs, because Jellyfin
  needs it for direct-play. ADR 0019.
- `ssh_args` at the top level and on `[[hosts]]`. A host list is appended after
  the global one, so a dedicated `-i KEY` needs no shell wrapper. The arguments
  land after the `ControlMaster` options, so connection persistence keeps
  working. ADR 0020.
- `env` on `[[hosts]]` and `local_env` at the top level. On SSH the remote
  command runs through `env 'K=V' ...`, with each pair quoted as one word. On
  the agent path the pair list travels in the hello. This replaces the worker
  wrapper that exported `OCL_ICD_VENDORS` and `LD_LIBRARY_PATH`. ADR 0021.

## Changes

- Agent protocol revision is now 2. The daemon refuses a client from another
  revision by name, so upgrade the client and the worker together.

## Upgrading

```bash
rrffmpeg --version   # must print rrffmpeg 0.6.0
```

Then set `fallback_local = false` on the GPU-less client, move the key from the
ssh wrapper into `ssh_args`, and move the worker exports into `[hosts.env]`.

Next: run a probe and a transcode through the entry point, then check
`rrffmpeg-stats`.
