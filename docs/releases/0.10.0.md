# 0.10.0

Release date: 2026-11-19

A Jellyfin setting can look enabled and still fail on the worker: Jellyfin
writes the knob, the dispatcher routes the job, and the encoder refuses it
after the job has taken a slot. `rrffmpeg jellyfin` closes that gap. It reads
Jellyfin's `encoding.xml`, turns each transcode setting into the arguments
Jellyfin would emit, and reports which hosts can serve it.

It changes no config key and no on-disk format.

## What changed

- `rrffmpeg jellyfin` compares the transcode settings with the `capabilities`
  of every host and prints one row per setting: the tokens it needs, the hosts
  that advertise them, and a verdict. `ok` means every host serves it,
  `partial` names the hosts that cannot, `broken` means no host can and exits 1,
  `unknown` means the one-frame probe cannot answer, `warn` flags a problem
  that is not about routing.
- The audit reuses `capabilities::required` on the argument sets Jellyfin can
  emit, so placement stays the only definition of what a job needs. A new
  token reaches the audit without a second rules table (ADR 0028).
- It reads `encoding.xml` with a flat tag scanner and no XML dependency. It
  never writes the file and needs no restart of Jellyfin.
- `--path` names the file, `--json` prints the rows for a script, `--host`
  limits the comparison, and `--probe` re-runs the one-frame probe instead of
  reading the declared list.
- `rrffmpeg capabilities` takes `--device`, and `jellyfin` reports `unknown`
  when `VaapiDevice` differs from the device the probe tested. The probe used
  to hardcode `/dev/dri/renderD128`, so a token could describe another GPU.
- The audit also checks that `TranscodingTempPath` falls under a host `paths`
  map, and warns when `EncodingThreadCount=-1` meets a host that runs several
  jobs at once.
- An HEVC row asks for `<family>_hevc` when that token exists, which is
  stricter than placement: ADR 0024 exists because a host can advertise the
  family and still fail the encoder.

## What an operator sees

```bash
rrffmpeg jellyfin --probe
```

One table, and exit code 1 when a setting cannot work. Nothing is written.

## Upgrading

Nothing to change. The new command is additive.

```bash
rrffmpeg --version
```

Expect `rrffmpeg 0.10.0`.

Next:

```bash
curl -fsSL https://github.com/vasilvestre/rrffmpeg/releases/download/v0.10.0/rrffmpeg-x86_64-unknown-linux-musl.tar.gz \
  | tar -xz -C /tmp
sudo install -m755 /tmp/rrffmpeg-x86_64-unknown-linux-musl/rrffmpeg /usr/local/bin/ffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/rrffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/ffprobe
rrffmpeg jellyfin --path /etc/jellyfin/encoding.xml --probe
```
