# 0.15.0

Release date: 2026-11-21

Two changes: the README stops being three documents in one file, and an absent
`concurrency` sizes a worker from the speed that worker reported. ADR 0034.

## Breaking change

- An absent `concurrency` on a host without `local = true` no longer stays at 1.
  The cap is sized from that host's own journal at startup: 1 until ten
  finishes of the content class, each longer than 60 s, reach 1.3x, then one
  job more. Write `concurrency = 1` to pin the old number.
- The example config ships `concurrency = "auto"` instead of `2`, so a copy of
  it starts at one job instead of oversubscribing the GPU. Set a number to keep
  a hand-set cap.

A fresh install therefore runs one transcode at a time until its journal holds
enough evidence. That is days on a home server, and it is the same number the
old default used. What changes is that the cap moves now.

## What changed

- The README is 156 lines: the pitch, a working install, a minimal config, the
  measured defects in one line each, the status, and an index of documents.
  Install starts at line 22 instead of 373.
- `docs/why.md` holds the alternatives, the seven measured defects of rffmpeg,
  how rrffmpeg answers them, and the evidence. `docs/configuration.md` holds the
  transports, the mode table, the placement rules and the Jellyfin audit.
  `docs/status.md` holds the checklist, what is next and the risks.
  `docs/operations.md` holds `rrffmpeg-stats` and the logging.
- An absent cap is `"auto"` on every host. The samples are keyed by the host
  that ran the job and carry the speed that host's ffmpeg printed, so a worker
  is sized from its own measurements, not the client's.
- The startup log says which rule set each cap: `concurrency left out, so it is
  sized from that host's journal`, or `light_concurrency left out, so it keeps
  2`.

## Upgrading

A config that sets `concurrency` behaves exactly as before. A config that
leaves the key out gains a cap that follows its journal. The journal format,
the slot files and the queue are untouched, so an old state dir replays
unchanged.
