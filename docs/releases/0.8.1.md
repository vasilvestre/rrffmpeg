# 0.8.1

Release date: 2026-11-18

This fixes a journal defect that made `rrffmpeg-stats` report jobs as open
after they had finished. It changes no config key and no on-disk record
format.

## What changed

- A process now reserves a block of journal sequence numbers at open, under
  an exclusive lock on `state_dir/journal.seq`. Before, each process read the
  same file tail and wrote the same numbers. Two events then shared a `seq`,
  and the reader kept only one of them.
- `rrffmpeg-stats` counts a `finished` with no matching `started` as
  `orphan_finish`, and a `reaped` with no start as `orphan_reaped`. It prints
  both on the records line and in `--json`. A future journal defect is
  visible instead of absorbed.
- `reaped` now counts only reaps that matched a start, so a lost start no
  longer inflates it.
- See [ADR 0025](../adr/0025-sequence-numbers-are-reserved-per-process.md).

Measured on the development host: opening the journal costs 18.5 us before
and 26.7 us after, once per process. Appending is unchanged: 1.79 us before
and 1.65 us after over 2000 appends.

## What an operator sees on an old journal

The 1036 lines already dropped by the old reader cannot be recovered. On a
journal written by 0.8.0 or earlier:

- `open` stays too high for the jobs whose `finished` line was dropped. Those
  jobs stay open until the records rotate out or you delete the journal.
- `records` still counts one entry per duplicate `seq`, so it stays lower
  than the line count.
- `orphan_finish` and `orphan_reaped` stay at zero, because the old reader
  dropped those lines before the summary saw them.

To tell new records from old, compare the highest `seq` with the value
printed before the upgrade, or start from an empty journal directory. New
records have unique `seq` values, and on a fresh journal the line count
equals the distinct `seq` count.

## Upgrading

```bash
rrffmpeg --version
```

Expect `rrffmpeg 0.8.1`. Then read the journal:

```bash
rrffmpeg-stats
```

On a live client, run a transcode and a few probes at once, then compare:

```bash
wc -l /dev/shm/rrffmpeg-rrj/journal
jq -r .seq /dev/shm/rrffmpeg-rrj/journal | sort -u | wc -l
```

The two numbers must match on records written after the upgrade. Before the
upgrade, the first number is larger by the lost lines.

Next:

```bash
curl -fsSL https://github.com/vasilvestre/rrffmpeg/releases/download/v0.8.1/rrffmpeg-x86_64-unknown-linux-musl.tar.gz \
  | tar -xz -C /tmp
sudo install -m755 /tmp/rrffmpeg-x86_64-unknown-linux-musl/rrffmpeg /usr/local/bin/ffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/rrffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/ffprobe
rrffmpeg-stats
```
