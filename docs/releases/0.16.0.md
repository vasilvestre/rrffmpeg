# 0.16.0

Release date: 2026-11-21

One addition: `rrffmpeg-stats --prometheus`, and a tested Alloy pipeline that
turns the journal into Grafana logs, counters and histograms.

## What changed

- `rrffmpeg-stats --prometheus` prints the journal figures in the Prometheus
  text exposition format, every duration in seconds and the percentiles behind
  a `quantile` label. The families: `rrffmpeg_dispatch_seconds`,
  `rrffmpeg_job_duration_seconds`, `rrffmpeg_speed_ratio`, `rrffmpeg_fps`,
  `rrffmpeg_open_jobs`, `rrffmpeg_jobs_finished`, `rrffmpeg_reaped_jobs`,
  `rrffmpeg_host_jobs`, `rrffmpeg_host_failures`, `rrffmpeg_jobs{kind}`,
  `rrffmpeg_classes{class}`, `rrffmpeg_exit_codes{code}`,
  `rrffmpeg_slots{host,class}`, `rrffmpeg_light_wait_over_1s` and
  `rrffmpeg_orphan_events{kind}`.
- A figure with no sample is absent, not zero. A p95 of zero would read as a
  measured zero, and a HELP line with no sample reads as a broken scrape.
- `rrffmpeg_slots` includes the recorded cap of a host that has no live sample
  yet, so a dashboard shows the cold-start number the next dispatch uses.
- `docs/operations.md` gains the Grafana section. Alloy tails the journal into
  Loki and derives `loki_process_custom_rrffmpeg_jobs_total`,
  `_jobs_ok_total` and two histograms, all carrying `host` and `event`, so
  `histogram_quantile()` works over any window. Counters cover history, and
  `--prometheus` covers the state only the whole journal can tell.
- `docs/index.html` states the three exports: human tables, `--json` for a log
  collector, `--prometheus` for a scrape.

## Why no metrics crate

`metrics`, `prometheus` and `opentelemetry-otlp` record observations inside a
long-lived process. rrffmpeg exits with each job, so they would reset every run
and make `rate()` meaningless. The Alloy pipeline is the long-lived process;
rrffmpeg only needs to keep writing its journal, and `--prometheus` prints a
snapshot for the figures the journal cannot carry as a log line.

## Upgrading

Nothing to do. The journal format, the slot files, the queue and the config file
are untouched, and `rrffmpeg-stats` keeps its human report and `--json`.
