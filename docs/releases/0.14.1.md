# 0.14.1

Release date: 2026-11-21

A startup listing waited for a transcode, and `rrffmpeg-stats` printed no cap.

## What changed

- `ffmpeg -version`, `-encoders`, `-hwaccels`, `-filters` and `-h` are startup
  listings, not transcodes. They now take a Light slot and answer in
  milliseconds instead of waiting `queue_wait_secs` behind a transcode. With
  an auto cap of 1 that wait was the full 60 s: measured 62.2 s before, 32 ms
  after. The journal records them under `probe`.
- A cold start writes a `Sized` line with `samples 0` instead of staying
  silent. A host that had measured nothing showed no decision at all, which is
  the case an operator most needs to see.
- `rrffmpeg-stats` prints a `size` row from that line. Before, it built its rows
  only from live samples, so an auto-sized host with no finished transcode
  showed nothing at all.

## Upgrading

Nothing to do. An old journal replays unchanged, and the new fields default to
empty.
