# 0.9.0

Release date: 2026-11-19

An AV1 job now waits for a host that proved it encodes AV1. Before this
release an `av1_vaapi` job asked only for `vaapi`, so it landed on any VAAPI
host, including a UHD 630 or an N100 that cannot encode AV1 at all, and failed
after taking a slot.

It changes no config key and no on-disk format.

## What changed

- Three new tokens: `vaapi_av1`, `qsv_av1` and `nvenc_av1`.
- `required()` adds `<family>_av1` when the encoder argument starts with
  `av1_`, and skips the HEVC and tone-map tokens for that job. An AV1 encoder
  is a codec choice, not a profile of HEVC, so `-profile:v main10` does not
  turn an AV1 job into a `vaapi_hevc10` job.
- The probe runs one extra 320x180 AV1 frame per encoder family, under the
  same `timeout 30` as every other test, and prints the token when the encode
  succeeds. Software AV1 (`libsvtav1`) still needs no token.
- `capabilities.rs` holds one table of probe cases instead of a token list and
  a command list that could drift apart. The printed order is unchanged
  except that `vaapi_tonemap` now comes last.
- The backend, the AV1 cut-off and the rejected alternatives are in
  [ADR 0027](../adr/0027-av1-is-a-codec-token.md).

## What an operator sees

On the current fleet no host encodes AV1, so an `av1_vaapi` job finds no
candidate and falls back per the configured policy. That is the intended
behaviour: a failed placement beats a failed transcode.

A host that can encode AV1 needs the new token in its `capabilities` list.
Existing lists keep working unchanged, because no job asks for an AV1 token
unless Jellyfin passes an AV1 encoder.

## Also fixed

The config example and the project page told you to list `["software"]` on a
host with no accelerator. No code produces or checks that token, and a
software job asks for no capability at all. The advice is gone.

## Upgrading

```bash
rrffmpeg --version
```

Expect `rrffmpeg 0.9.0`. Then re-read the capabilities of each worker and
paste the new line:

```bash
rrffmpeg capabilities worker
```

Next:

```bash
curl -fsSL https://github.com/vasilvestre/rrffmpeg/releases/download/v0.9.0/rrffmpeg-x86_64-unknown-linux-musl.tar.gz \
  | tar -xz -C /tmp
sudo install -m755 /tmp/rrffmpeg-x86_64-unknown-linux-musl/rrffmpeg /usr/local/bin/ffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/rrffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/ffprobe
rrffmpeg capabilities worker
```
