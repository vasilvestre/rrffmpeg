# 0.8.0

Release date: 2026-11-18

Placement now matches what a driver really does, not what it lists. Two GPUs
from the same vendor, both printing `h264_vaapi` and `hevc_vaapi` in
`ffmpeg -encoders`, differed on 10-bit HEVC and tone mapping by a factor of
"works" against "fails after taking a slot".

## What changed

- Capabilities are sub-tokens: `vaapi`, `vaapi_hevc`, `vaapi_hevc10`,
  `vaapi_tonemap`, `vaapi_vpp`, `qsv`, `nvenc`. A job needs all of the tokens
  its arguments imply, not one.
- The arguments decide. A `*_vaapi` encoder requires `vaapi`; `main10` or
  `p010` adds `vaapi_hevc10`; a `tonemap_vaapi` filter adds
  `vaapi_tonemap`. Placement still reads memory only: nothing probes on the
  dispatch path.
- New subcommand, on the client: `rrffmpeg capabilities [host]`. It runs one
  frame per token on each worker and prints the exact TOML rows to paste. A
  driver update is one command away from a correct map.
  See [ADR 0024](../adr/0024-declared-capabilities.md).

## Measured

Same 4K HEVC 10-bit source, one frame per test, on two shared seedboxes:

| | i5-6500T, HD 530 | i5-7500T, UHD 630 |
|---|---|---|
| `h264_vaapi` | yes | yes |
| `hevc_vaapi` main | yes | yes |
| `hevc_vaapi` main10 | no | yes |
| 10-bit decode into a VAAPI surface | no | yes |
| `tonemap_vaapi` | no, "driver doesn't support HDR" | yes |
| `h264_qsv` | yes | yes |

Both list `hevc_vaapi` in `ffmpeg -encoders`. Before this release, a 10-bit job
could land on the host that cannot encode it.

## Breaking change

A host whose `capabilities` list is non-empty now has to list every token a
job needs. With one worker, set the list to what `rrffmpeg capabilities`
prints. A single `["vaapi"]` host no longer accepts a `main10` job: it waits
for an eligible host, then falls back or exits 1 as configured. An empty list
still accepts any job.

## Upgrading

```bash
rrffmpeg --version
```

Expect `rrffmpeg 0.8.0`. Then, on the client:

```bash
rrffmpeg capabilities
```

Paste each printed line into the matching `[[hosts]]` block.

Next:

```bash
curl -fsSL https://github.com/vasilvestre/rrffmpeg/releases/download/v0.8.0/rrffmpeg-x86_64-unknown-linux-musl.tar.gz \
  | tar -xz -C /tmp
sudo install -m755 /tmp/rrffmpeg-x86_64-unknown-linux-musl/rrffmpeg /usr/local/bin/ffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/rrffmpeg
sudo ln -sf /usr/local/bin/ffmpeg /usr/local/bin/ffprobe
rrffmpeg capabilities
```
