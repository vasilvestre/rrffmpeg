# 0.12.0

Release date: 2026-11-19

Placement chose a host from its tokens, its down flag and a free slot. It never
asked whether the host could open the input file, and it broke ties with the
order of the `[[hosts]]` blocks. A two-host install with an archive box and a
GPU worker got that wrong: a title only the archive box mounts was placed on
the worker, ffmpeg exited 254, and nothing retried it. The workaround was to
reorder the blocks, which is what this release removes.

## What changed

- A host can declare the roots it reads: `reads = ["/mnt/archive"]`. Entries
  are absolute paths as the host sees them, after its own path maps. Placement
  maps each `-i` value for the candidate host, then skips a host whose roots
  cover none of the inputs. The check runs before the slot check, so a host
  that cannot read the job also earns no queue ticket. ADR 0030.
- Placement is now a total order and never reads the file order: a host that
  needs no ssh wins a job that needs no accelerator token, then a higher
  `prefer`, then the lower running/concurrency ratio, then the host name.
  `prefer` defaults to 0, which is a tie. Swapping two `[[hosts]]` blocks
  changes nothing. ADR 0031.
- `rrffmpeg jellyfin` no longer calls a VAAPI tone-map setting `ok` when
  `EnableVppTonemapping` is off. Jellyfin builds `tonemap_opencl` in that case,
  and the probe proves `tonemap_vaapi` only, so the row is `unknown` and names
  the filter the client will emit. Turning VPP on restores the token check,
  and the row is `ok` when the host proves `vaapi_tonemap` and `vaapi_vpp`.
- The config refuses a relative `reads` entry. It would match no absolute
  input, and the host would silently take no job.

## Upgrading

Nothing to change. A config that declares neither `reads` nor `prefer` routes
as it did, with one deliberate exception: a job that needs no accelerator token
now prefers a host that needs no ssh. A software encode (`libx264`, for
example) with a `local = true` host present stays on the client, and a config
that mixes ssh and agent transports sends it to the agent host instead. Add
`prefer` to any host you want first among equals.

A config where every host needs ssh keeps every placement it had, because the
first rule then ties and the load ratio still decides.

To route by what a machine can mount:

```toml
[[hosts]]
name = "archive"
reads = ["/mnt/archive"]
prefer = 10

[[hosts]]
name = "worker"
concurrency = 2
capabilities = ["vaapi", "vaapi_hevc"]
reads = ["/home/bob/media"]

[[hosts.paths]]
from = "/home/alice"
to = "/home/bob/media"
```

Check that a root is written the way the host sees it, not the way the client
does: the value must match after the host's own path maps.

```bash
rrffmpeg --version
```

Expect `rrffmpeg 0.12.0`.
